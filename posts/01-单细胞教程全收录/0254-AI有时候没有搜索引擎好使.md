**二、AI指点小弯路**

如果把代码和运行日志提交给AI，那你收获到的回答是：

这个报错发生在 `inferCNV` 进行Leiden聚类前的“计算近邻图”步骤，核心问题是**矩阵中出现了` NA`（缺失值）**，导致邻接矩阵的索引分配失败。这不是你的数据原本有缺失，而很可能是计算过程中的数值问题。

为了高效定位和解决，请按以下顺序进行检查。

### 🔍 第一步：定位并处理NA值（首选方案）

运行以下诊断代码，检查产生问题的核心对象：

  *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *

```r
# 1. 检查 infercnv_obj 中的肿瘤细胞表达矩阵（最可能出问题的位置）# 假设你的 inferCNV 对象名为 `infercnv_obj`tumor_expr_matrix <- infercnv_obj@expr.datacat("肿瘤细胞表达矩阵中 NA 的数量:", sum(is.na(tumor_expr_matrix)), "\n")cat("矩阵维度:", dim(tumor_expr_matrix), "\n")
# 2. 如果有NA，查看其分布if(sum(is.na(tumor_expr_matrix)) > 0) {# 查看哪些基因（行）包含NA  na_genes <- rowSums(is.na(tumor_expr_matrix)) > 0cat("包含 NA 的基因数量:", sum(na_genes), "\n")
# 查看哪些细胞（列）包含NA  na_cells <- colSums(is.na(tumor_expr_matrix)) > 0cat("包含 NA 的细胞数量:", sum(na_cells), "\n")
# 可选：查看少量NA的具体位置which(is.na(tumor_expr_matrix), arr.ind = TRUE)[1:10, ]}
```

如果发现 `NA`，通常是平滑或去中心化步骤中出现了数值计算问题。可以用以下方法**安全地替换** （例如用基因的中位数）：

  *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *   *

```r
# 3. 替换NA（如果上一步发现NA）if(sum(is.na(tumor_expr_matrix)) > 0) {  # 按基因（行）计算中位数，忽略NA  gene_medians <- matrixStats::rowMedians(tumor_expr_matrix, na.rm = TRUE)
  # 为每个NA找到对应的基因，并用该基因的中位数替换  na_indices <- which(is.na(tumor_expr_matrix), arr.ind = TRUE)  for(i in1:nrow(na_indices)) {    row_idx <- na_indices[i, 1]    tumor_expr_matrix[row_idx, na_indices[i, 2]] <- gene_medians[row_idx]  }
  # 验证NA已处理  cat("替换后，NA的数量:", sum(is.na(tumor_expr_matrix)), "\n")
  # 将处理后的矩阵放回对象  infercnv_obj@expr.data <- tumor_expr_matrix}
```

### 第二步：检查版本与数据转换

如果第一步**没有发现NA** ，问题可能出在数据转换的兼容性上：

  1. **检查包版本** ：确保你使用的 `infercnv` 和 `Seurat` 是比较新的版本。某些旧版本在交互时可能存在bug。

  *   *

```
packageVersion("infercnv")packageVersion("Seurat")
```

  1. **检查矩阵类型** ：警告 `Warning: Data is of class matrix. Coercing to dgCMatrix.` 表明内部进行了一次类型转换。虽然这通常是安全的，但可以尝试**手动提供一个稀疏矩阵** 。

     * 注意：如果你的数据量极大（如超过10万细胞），`as.matrix` 可能会耗尽内存。请优先使用稀疏矩阵操作。

**三、答案早在github中**

事实上，我的矩阵中没有任何的NA，跟着AI检查了半天也没有解决问题，如果你用搜索引擎检索一下，可以发现网友遇到过类似的问题(https://github.com/broadinstitute/infercnv/issues/396)由于在计算过程中R使用了科学计数法，把100000以上的数字以1e5这种形式表示了，因此无法参与后续的计算。因此，大家只需要在执行infercnv之前加上一个options(scipen = 100)即可解决这一问题。
![](https://mmbiz.qpic.cn/mmbiz_png/ImlBFVOwwpyIofhFSKQBZRS1ccu51YSWMibJA2LoSzb3guWbGovA4QgQwWrD11iaicp1DzGiaicG3b3puALnHlykJvQ/640?wx_fmt=png&from=appmsg)不过，你大概率还会遇到一个新的问题（别笑，你也过不了第二关）：由于你的细胞数量超过了10w，那么infercnv输出热图时会向你索取千万TB级别的内存（是的你没看错）。![](https://mmbiz.qpic.cn/mmbiz_png/ImlBFVOwwpyIofhFSKQBZRS1ccu51YSWZibahRicqJNZmic9UThc2uVcvGBwcRx9xBwEOg3Ps9YeBbUgTzDJZEkeg/640?wx_fmt=png&from=appmsg)这时你就只能选择no_plot = T，在结果输出到本地的时候通过[downsample](<https://mp.weixin.qq.com/s?__biz=MzAwMzIzOTk5OQ==&mid=2247530367&idx=1&sn=f7452a93145295bd6dfc4a7e571413d6&scene=21#wechat_redirect>)自行绘制热图了。AI未必能替你解决所有问题，常见的bug其实都被遇到过，且被前辈们总结过解决方案，别太迷信AI，该检索的时候还是得搜一搜![](https://res.wx.qq.com/t/wx_fed/we-emoji/res/assets/Expression/Expression_14@2x.png)。
